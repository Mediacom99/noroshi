**Create directory `.github/workflows/` and file `.github/workflows/ci.yml`.**

Write the following workflow (per D-01, D-05, D-06, D-07, D-08, D-09):

```yaml
name: CI

on:
  push:
    branches: [develop, main]
  pull_request:
    branches: [develop, main]

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  lint:
    name: lint
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - uses: actions/checkout@v6
      - uses: actions/setup-go@v6
        with:
          go-version-file: 'go.mod'
      - uses: golangci/golangci-lint-action@v9
        with:
          version: v2.11.4

  build-and-test:
    name: build-and-test
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - uses: actions/checkout@v6
      - uses: actions/setup-go@v6
        with:
          go-version-file: 'go.mod'
      - name: Build
        run: CGO_ENABLED=0 go build ./cmd/monitor/
      - name: Vet
        run: go vet ./...
      - name: Test
        run: go test ./...
```

Key design decisions reflected:
- **D-01:** `on.push.branches` and `on.pull_request.branches` both include `[develop, main]`
- **D-05:** Two jobs (`lint` and `build-and-test`) with NO `needs:` between them -- they run in parallel
- **D-06:** `actions/setup-go@v6` includes automatic Go module caching (GOCACHE + GOMODCACHE) by default
- **D-07:** `timeout-minutes: 10` on both jobs
- **D-08:** `go-version-file: 'go.mod'` reads `go 1.26.1` from go.mod -- no hardcoded version
- **D-09:** `concurrency.group` with `cancel-in-progress: true` cancels stale runs on same branch

The lint job uses `golangci-lint-action@v9` which downloads golangci-lint v2.11.4, reads `.golangci.yml` from repo root automatically, and runs against the full codebase.

The build-and-test job mirrors the three commands from CLAUDE.md's commit rules:
1. `CGO_ENABLED=0 go build ./cmd/monitor/` (CICD-03)
2. `go vet ./...` (CICD-04)
3. `go test ./...`
